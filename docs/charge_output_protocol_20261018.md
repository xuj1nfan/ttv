# 罪名输出协议开发集对照（2026-10-18）

固定同一份 CAIL2018 筛选后的 100 例开发集、202 个训练集候选罪名、Qwen 服务及
其他解码参数，比较三种最终输出协议。编号方案也把系统提示中的候选列表改成带编号格式；
JSON Schema 方案保留自由输出时的提示文字，仅修改最终阶段的响应约束。
三轮都保留原始响应，未做重试或按金标准修复。
各轮独立运行，运行快照和逐案预测均在对应结果目录。

| 最终阶段协议 | 准确率 | 无效标签 | 运行错误 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 普通 JSON 中自由输出罪名文字 | 66/100 | 12 | 0 | [`dev-full-20261018`](../results/dev-full-20261018/) |
| 从 202 个编号中输出整数 ID | 46/100 | 0 | 0 | [`dev-id-baseline-20261018`](../results/dev-id-baseline-20261018/) |
| 输出罪名文字，最终请求用 JSON Schema enum 限定为官方标签 | **70/100** | **0** | **0** | [`dev-schema-baseline-20261018`](../results/dev-schema-baseline-20261018/) |

编号方案虽然消除了格式错误，但出现 29 例由对变错、9 例由错变对。典型案例的前两阶段
已分析出正确罪名，最终返回的编号却对应无关罪名，因此没有采用该方案作为默认协议。

JSON Schema enum 方案保持原有按罪名文字推理的提示，只在最终请求限制 `charge`
字段为训练词表中的完整字符串。本地服务已通过真实请求验证支持该格式；
它对应 [vLLM 的 JSON Schema 响应格式](https://docs.vllm.ai/en/stable/examples/features/structured_outputs/)。
与自由输出相比，100 例逐案配对有 4 例由错变对、0 例由对变错；
旧协议中有效的 88 个输出全部保持原标签，旧协议的 12 个无效输出发生变化，
其中 4 个改为正确标签，8 个仍然选错罪名。主模型报告的总 tokens 分别为
627,693 和 627,710。这个结果说明格式问题得到解决，但不意味着剩余错例都是格式问题。

当前默认代码使用 `charge_json_schema_enum_v1`，运行快照的 `final_output_protocol`
记录协议名称。后续开发集 shadow、self_check、nli_conflict 与正式测试都应使用同一协议；
旧协议结果只作为开发阶段对照，不能与新协议的其他实验组直接计算反馈收益。
100 例开发集是过滤子集，本对照不能作为官方完整 benchmark 成绩。
