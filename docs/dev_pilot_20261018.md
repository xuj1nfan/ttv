# CAIL2018 开发集首次真实模型试跑（2026-10-18）

这次试跑使用本机 `qwen3-8b` chat-completions 服务、服务器现有的
`xlm-roberta-large-xnli`，以及从 CAIL2018 `exercise_contest` 验证文件筛出的
100 个单被告、单罪名、短事实案件。数据规则和运行方法见 [first_round.md](first_round.md)。
本报告记录的是当时最终阶段以普通 JSON 模式输出 `charge` 文字的旧协议；
后续约束输出试跑另存结果，不能把两种协议的分数当作同一实验配置。
原始运行快照、逐案预测和检查点记录在
[`results/dev-full-20261018/`](../results/dev-full-20261018/)；
完整统计见 [`summary.json`](../results/dev-full-20261018/summary.json)。

shadow 组只记录 NLI 判断，不发送反馈，因此这次结果**不检验 NLI 对罪名预测的改善**。
两组正确/错误的案件完全相同，但有 4 例具体输出不同；同一请求 seed 不保证服务端完全确定性。
200 次核查中，NLI 输出 support 153 次、insufficient 46 次、conflict 1 次；
同案相同命题重复核查了 53 次，实际只有 147 个不同的“案件＋命题”组合。
这些数是模型输出分布，**不是 NLI 准确率**。

需要先检查两类问题：

1. 官方罪名标签包含方括号形式，例如 `骗取[贷款、票据承兑、金融票证]`；
   Qwen 有时输出自然语言中的具体罪名 `骗取贷款`。当前评测按官方完整字符串精确匹配，
   因此这类输出记为非法标签且计错。不能在看到开发集结果后暗中把它映射为正确答案；
   后续可以在开发集明确设计“从候选表选 ID”的输出协议，再重新试跑并冻结协议。
2. 初步人工抽查发现若干高置信 insufficient 可疑例：`cail-dev-3501` 的原文给出了
   公交候车亭数量、玻璃数量和估价，模型命题复述了这些数字，NLI 仍给出约 0.991 的
   insufficient 概率；`cail-dev-1672` 的入学名义骗财命题也出现类似情况。
   这些只是定向抽查，不代表全量误判率；复合命题或原文表述差异需要逐条人工确认。
